# AOEffect改为选择性效果的开发日志

## 一、项目背景

随着项目的深入开发，我们需要实现更精细的视觉效果控制，特别是在环境遮蔽(AO)效果方面。标准的`AOEffect`会对整个场景应用环境遮蔽，但在某些场景中，我们希望只对特定对象应用这种效果，其他对象则保持原样。例如，在展示产品时，我们希望主要产品具有精细的阴影细节，而背景或次要元素则可以简化处理。

本开发日志记录了我们将标准`AOEffect`改造为支持选择性处理的`SelectiveAOEffect`的全过程，包括遇到的主要问题、解决方案以及详细的实现流程。

## 二、开发过程中遇到的主要挑战

### 1. 对象识别与排除问题

**问题描述**：
如何在渲染过程中识别并排除特定对象，使其不受AO效果影响？标准的PostProcessing框架不直接支持对特定对象的选择性处理。

**解决思路探索**：
1. ✗ 尝试使用图层(Layers)：初期我们尝试将不需要AO的对象放置在特定图层，但这种方法与场景的其他图层管理冲突，且无法解决对象间的遮挡问题。
2. ✗ 尝试修改WebGLRenderer：考虑直接修改渲染器，但这会破坏框架的兼容性且实现复杂。
3. ✓ 使用材质标记法：最终我们采用了通过临时修改材质属性（特别是发光值）来标记对象，然后在着色器中识别这些标记的方法。

### 2. 渲染顺序与数据流问题

**问题描述**：
实现过程中，我们发现被排除对象在最终渲染中仍然受到AO影响，或者出现"对象变白"的问题。

**原因分析**：
1. 渲染顺序错误：在多通道渲染过程中，场景状态的准备和恢复顺序不正确。
2. 数据流不完整：某些必要的纹理和参数未正确传递给着色器。
3. 材质恢复不及时：对象的临时高亮材质未在正确的时机恢复。

### 3. 性能与兼容性问题

**问题描述**：
选择性处理增加了额外的渲染通道和计算，导致性能下降，同时与现有的后处理效果链兼容性存在问题。

**表现症状**：
1. 帧率明显下降，特别是在复杂场景或多个选择性效果同时使用时。
2. 与其他后处理效果（如景深、辉光）一起使用时出现渲染错误或视觉伪影。

## 三、解决方案详解

### 1. 对象标记与识别机制

我们采用了"超高发光值标记法"来识别需要排除的对象：

```javascript
// 标记对象的代码
selectionItems.forEach(object => {
    if (object && object.isMesh) {
        // 存储原始材质状态
        this.originalMaterials.set(object.uuid, {
            material: object.material,
            emissive: object.material.emissive ? object.material.emissive.clone() : null
        });

        // 设置超高发光值作为标记
        if (object.material.emissive) {
            object.material._originalEmissive = object.material.emissive.clone();
            object.material.emissive.set(2000, 2000, 2000);  // 超高值确保在着色器中可识别
        }
    }
});
```

在着色器中，我们通过检测像素亮度来识别这些对象：

```glsl
// 着色器中的识别代码
// 忽略超亮物体的阈值
#define IGNORE_BRIGHTNESS_THRESHOLD 20.0

// 计算输入颜色的亮度
float brightness = max(max(inputColor.r, inputColor.g), inputColor.b);

// 检测超亮物体（被标记为不参与AO的对象）
if (brightness > IGNORE_BRIGHTNESS_THRESHOLD) {
    // 如果检测到超亮物体，直接返回原始颜色，不应用AO
    outputColor = inputColor;
    return;
}
```

### 2. 多阶段渲染管线设计

为解决渲染顺序和数据流问题，我们设计了一个明确的多阶段渲染流程：

1. **场景准备阶段**：标记需要排除的对象
2. **深度渲染阶段**：渲染包含标记对象的场景深度
3. **场景恢复阶段**：恢复对象的原始材质状态
4. **AO计算阶段**：使用深度信息计算环境遮蔽
5. **降噪处理阶段**：对AO结果进行降噪处理
6. **选择性混合阶段**：基于标记信息选择性地应用AO效果

关键代码实现：

```javascript
update(renderer, inputBuffer, outputBuffer, deltaTime, stencilTest, depthPass) {
    // 1. 准备场景 - 标记对象
    this.prepareScene();
    
    // 保存当前渲染目标
    const currentRenderTarget = renderer.getRenderTarget();
    
    // 2. 渲染深度
    this.renderPass.render(renderer, this.renderTargetAO, this.renderTargetAO, deltaTime, true);
    
    // 3. 立即恢复场景状态，避免对象变白问题
    this.restoreScene();
    
    // 获取深度纹理
    const filteredDepthTexture = this.renderTargetAO.depthTexture;
    
    // 设置原始场景纹理
    this.uniforms.get("inputBuffer").value = this.renderTargetAO.texture;
    
    // 4. 使用深度信息渲染AO效果
    this.aoPass.fullscreenMaterial.uniforms.depthTexture.value = filteredDepthTexture;
    this.aoPass.render(renderer);
    
    // 5. 对AO结果进行降噪
    this.poissionDenoisePass.render(renderer);
    
    // 6. 设置最终AO纹理用于选择性混合
    this.uniforms.get("inputTexture").value = this.poissionDenoisePass.texture;
    
    // 恢复原始渲染目标
    renderer.setRenderTarget(currentRenderTarget);
}
```

### 3. 性能优化与兼容性改进

为解决性能和兼容性问题，我们采取了以下措施：

1. **分辨率缩放**：引入`resolutionScale`参数，允许降低AO计算的分辨率以提高性能
   ```javascript
   this.aoPass.setSize(width * this.resolutionScale, height * this.resolutionScale);
   ```

2. **智能缓存机制**：缓存对象的原始状态，减少状态切换开销
   ```javascript
   // 避免重复处理相同大小的渲染目标
   if (width === this.lastSize.width && height === this.lastSize.height && 
       this.resolutionScale === this.lastSize.resolutionScale) {
       return;
   }
   ```

3. **条件渲染逻辑**：根据实际需要执行不同的渲染路径
   ```javascript
   // 只有在必要时才执行额外的渲染通道
   if (this.ignoreBackground || !inverted || selection.size > 0) {
       // 执行特殊处理通道...
   }
   ```

4. **调试模式支持**：添加多种调试模式，便于识别和解决兼容性问题
   ```javascript
   // 调试模式检查
   const debugMode = this.uniforms.get("debugMode").value;
   if (debugMode > 0) {
       console.log(`当前调试模式: ${debugMode} (1=亮度, 2=AO强度, 3=AO值)`);
   }
   ```

### 数据流说明

1. **输入数据**:
   - 原始场景（Scene）
   - 相机参数（Camera）
   - 选择对象列表（Selection）
   - AO参数配置（距离、强度、颜色等）

2. **中间数据**:
   - 渲染目标颜色纹理（renderTargetAO.texture）
   - 渲染目标深度纹理（renderTargetAO.depthTexture）
   - AO计算结果（aoPass.texture）
   - 降噪后的AO结果（poissionDenoisePass.texture）

3. **输出数据**:
   - 最终混合结果（mainImage输出到outputColor）

4. **核心着色器Uniform变量**:
   ```javascript
   uniforms: new Map([
       ["inputTexture", new Uniform(null)],     // AO纹理
       ["inputBuffer", new Uniform(null)],      // 原始场景颜色纹理
       ["depthTexture", new Uniform(null)],     // 深度纹理
       ["power", new Uniform(0)],               // AO强度
       ["color", new Uniform(new Color("black"))], // AO颜色
       ["brightnessThreshold", new Uniform(0.7)],  // 亮度阈值
       ["debugMode", new Uniform(0)]            // 调试模式
   ])
   ```

## 五、开发过程中的重要里程碑

### 里程碑1: 基本标记机制实现（第1周）

首先实现了基本的对象标记和识别机制，能够在着色器中区分标记的对象：

- 使用Selection类管理需要排除的对象
- 实现材质临时修改和恢复机制
- 在着色器中添加基本的亮度检测

**遇到的问题**：标记对象在其他渲染通道中也变为高亮，导致视觉错误。

**解决方案**：分离渲染通道，确保在完成特定渲染后立即恢复材质状态。

### 里程碑2: 渲染管线重构（第2周）

重新设计了整个渲染管线，解决了渲染顺序和数据流问题：

- 创建专用的渲染目标和通道
- 实现明确的多阶段渲染流程
- 确保场景状态在各阶段间正确转换

**遇到的问题**：深度纹理不正确，导致AO效果在标记对象边缘出现伪影。

**解决方案**：确保深度纹理正确创建和传递，添加深度检查逻辑。

### 里程碑3: 自适应效果优化（第3周）

增加了基于场景特征（如亮度）的自适应效果调整：

- 实现亮度自适应的AO强度
- 添加多种调试模式
- 优化混合策略

**遇到的问题**：在某些光照条件下，自适应效果过强或过弱。

**解决方案**：引入亮度阈值参数，允许用户调整自适应效果的敏感度。

### 里程碑4: 性能优化和稳定性改进（第4周）

解决性能问题并提高整体稳定性：

- 实现分辨率缩放选项
- 添加智能缓存机制
- 优化渲染条件判断
- 完善错误处理和资源管理

**遇到的问题**：多个选择性效果同时使用时性能下降严重。

**解决方案**：实现效果间的资源共享机制，如共用深度通道和渲染目标。

## 六、调试技巧与实用经验

### 调试模式的使用

我们实现了多种调试模式，帮助可视化不同的处理阶段：

```javascript
// 调试模式: 0=正常, 1=显示亮度, 2=显示AO强度, 3=显示AO值
if (debugMode == 1) {
    // 显示亮度值
    float normalizedBrightness = clamp(perceptualBrightness / brightnessThreshold, 0.0, 1.0);
    outputColor = vec4(vec3(normalizedBrightness), 1.0);
    return;
} else if (debugMode == 2) {
    // 显示AO强度值
    outputColor = vec4(vec3(aoStrength), 1.0);
    return;
} else if (debugMode == 3) {
    // 显示最终AO值
    outputColor = vec4(vec3(ao), 1.0);
    return;
}
```

通过切换这些模式，我们可以迅速定位问题所在：

- 模式1：检查亮度计算是否正确，标记对象是否被正确识别
- 模式2：验证AO强度的自适应效果是否符合预期
- 模式3：查看原始AO计算结果，检查基础AO算法是否正常工作

### 对象管理最佳实践

在处理大量对象时，我们发现以下方法非常有效：

1. **分组管理**：将相关对象组织为组，一次性添加或移除
2. **延迟处理**：不要在每次对象变化时立即更新效果，而是在渲染前统一处理
3. **缓存验证**：使用UUID作为键，确保不会重复处理相同对象

### 避免常见陷阱

开发过程中，我们发现了一些需要特别注意的问题：

1. **材质共享问题**：当多个对象共享同一材质时，修改一个对象会影响所有使用该材质的对象
2. **渲染目标清理**：确保在每次渲染前正确清理渲染目标，避免残留数据
3. **纹理尺寸匹配**：确保所有相关纹理（颜色、深度等）尺寸一致，避免采样错误

## 七、效果对比与结论

### 效果对比

| 特性 | 原始AOEffect | 选择性AOEffect |
|------|-------------|---------------|
| 处理范围 | 整个场景 | 可选择特定对象 |
| 自适应效果 | 无 | 基于亮度的自适应强度 |
| 调试能力 | 有限 | 多种调试模式 |
| 性能影响 | 较小 | 中等（可通过分辨率调整） |
| 混合策略 | 简单混合 | 智能混合考虑分辨率和效果一致性 |

### 核心改进总结

1. **选择性处理**：实现了对特定对象的排除机制，使AO效果只应用于需要的对象
2. **自适应效果**：根据场景亮度动态调整AO强度，提高真实感
3. **渲染管线重构**：设计了更灵活的多阶段渲染流程，支持复杂的选择性处理
4. **调试与性能优化**：添加了多种调试模式和性能优化选项

### 未来改进方向

1. **多种标记方式支持**：除了使用emissive值，增加更多标记对象的方法，如自定义材质属性
2. **共享资源机制**：实现多个选择性效果间的资源共享，减少重复渲染和计算
3. **GPU实例优化**：针对大量相似对象的情况，实现基于GPU实例的高效标记机制
4. **自动参数调整**：基于场景分析自动调整参数，减少手动配置的需要

## 八、总结

通过本次开发，我们成功将标准的`AOEffect`改造为功能更强大的选择性环境遮蔽效果。这一改进不仅满足了项目的实际需求，还为我们积累了丰富的经验和技术，为实现其他选择性后处理效果奠定了基础。

选择性着色器的核心思想 - 在后处理阶段区分和选择性处理特定对象 - 是一种强大的技术，可以应用于各种视觉效果中，如选择性景深、选择性辉光等。通过本文记录的开发历程和解决方案，我们希望能为其他开发者提供有价值的参考和启发。
