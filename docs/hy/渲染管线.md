## 渲染管线概述

### 基本架构

```
┌─────────────────────────────────────────────────────────────┐
│                      EffectComposer                          │
│  ┌────────────────────────────────────────────────────────┐ │
│  │ Ping-Pong Buffer (inputBuffer ↔ outputBuffer)         │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐     │
│  │ RenderPass   │→ │ EffectPass   │→ │ CompatPass   │→ 屏幕│
│  │  (场景渲染)  │  │  (内置效果)  │  │  (Three.js)  │     │
│  └──────────────┘  └──────────────┘  └──────────────┘     │
└─────────────────────────────────────────────────────────────┘
```

### 核心概念

- **Pass**: 渲染管线中的一个处理步骤
- **Buffer**: WebGLRenderTarget，存储中间渲染结果
- **Ping-Pong**: 双缓冲交替机制，避免纹理读写冲突

## EffectComposer 核心机制

### 初始化

```javascript
// 文件: src/core/EffectComposer.js (672-759行)

constructor(renderer, options) {
    this.renderer = renderer;
    this.inputBuffer = new WebGLRenderTarget(...);   // 读取缓冲区
    this.outputBuffer = new WebGLRenderTarget(...);  // 写入缓冲区
    this.passes = [];  // Pass数组
}
```

### 渲染循环

```javascript
render(deltaTime) {
    let inputBuffer = this.inputBuffer;
    let outputBuffer = this.outputBuffer;
    
    // 1. 渲染 RenderPass（如果存在）
    if (renderPass?.isRenderPass) {
        renderPass.render(renderer, inputBuffer, outputBuffer, ...);
    }
    
    // 2. 遍历所有后处理 Pass
    for (const pass of this.passes) {
        if (pass.enabled && !pass.isRenderPass) {
            // 执行 Pass 渲染
            pass.render(renderer, inputBuffer, outputBuffer, deltaTime, ...);
            
            // 3. Ping-Pong 缓冲区交换
            if (pass.needsSwap) {
                const buffer = inputBuffer;
                inputBuffer = outputBuffer;  // 输出变成输入
                outputBuffer = buffer;       // 输入变成输出
            }
        }
    }
}
```

### 乒乓缓冲机制

```
帧 N：
┌─────────────┐        ┌─────────────┐
│ inputBuffer │  读取  │             │
│   (纹理A)   │ ────→  │   Pass 1    │
└─────────────┘        │             │
                       │  处理+写入  │
┌─────────────┐        │             │
│outputBuffer │  写入  │             │
│   (纹理B)   │ ←────  └─────────────┘
└─────────────┘

交换后（needsSwap=true）：
inputBuffer  = 纹理B  (原outputBuffer)
outputBuffer = 纹理A  (原inputBuffer)

帧 N+1：
┌─────────────┐        ┌─────────────┐
│ inputBuffer │  读取  │             │
│   (纹理B)   │ ────→  │   Pass 2    │
└─────────────┘        │             │
                       │  处理+写入  │
┌─────────────┐        │             │
│outputBuffer │  写入  │             │
│   (纹理A)   │ ←────  └─────────────┘
└─────────────┘
```

## Pass 类型对比

### 1️⃣ RenderPass

**文件**: `src/passes/RenderPass.js`

**功能**: 渲染场景到缓冲区，可选 G-Buffer 生成

```javascript
class RenderPass extends Pass {
    isRenderPass = true;
    needsSwap = false;  // 不需要交换缓冲区
    
    render(renderer, inputBuffer, outputBuffer, deltaTime) {
        // 渲染场景
        renderer.setRenderTarget(outputBuffer);
        renderer.render(scene, camera);
        
        // 可选：渲染 G-Buffer
        if (this.enableGBuffer) {
            this.renderGBuffer(renderer);
        }
    }
}
```

**特点**:
- ✅ 唯一标识: `isRenderPass = true`
- ✅ 不交换缓冲区: `needsSwap = false`
- ✅ 输出到 `outputBuffer`
- ✅ 支持 G-Buffer 模式

**G-Buffer 输出**:
- `gColor` - 颜色通道
- `gNormal` - 法线通道
- `gDepth` - 深度通道
- `gPosition` - 世界坐标（可选）
- `gObjectId` - 对象ID（可选）

---

### 2️⃣ EffectPass

**文件**: `src/passes/EffectPass.js`

**功能**: 处理内置 Effect 系统的效果（如 BloomEffect、SSAOEffect）

```javascript
class EffectPass extends Pass {
    needsSwap = true;  // 需要交换缓冲区
    
    constructor(camera, ...effects) {
        this.effects = effects;
        this.fullscreenMaterial = new EffectMaterial(...);
    }
    
    render(renderer, inputBuffer, outputBuffer, deltaTime) {
        // 1. 更新所有 Effect
        for (const effect of this.effects) {
            effect.update(renderer, inputBuffer, deltaTime);
        }
        
        // 2. 合成渲染
        this.afterRender(renderer, inputBuffer, outputBuffer, deltaTime);
    }
    
    afterRender(renderer, inputBuffer, outputBuffer, deltaTime) {
        // 设置输入纹理
        this.fullscreenMaterial.inputBuffer = inputBuffer.texture;
        
        // 渲染到输出
        renderer.setRenderTarget(this.renderToScreen ? null : outputBuffer);
        renderer.render(this.scene, this.camera);
    }
}
```

**特点**:
- ✅ 使用 `EffectMaterial` 合成材质
- ✅ 支持多个 Effect 合并
- ✅ 自动管理 Shader 合成
- ✅ 需要交换缓冲区: `needsSwap = true`

**渲染流程**:
```
Effect.update()           ← 各Effect计算（可能渲染到自己的RT）
    ↓
EffectMaterial            ← 合成所有Effect的Shader
    ↓
render(scene, camera)     ← 全屏四边形渲染
    ↓
outputBuffer              ← 输出结果
```

### 3️⃣ EnhancedThreeCompatPass

**文件**: `src/passes/EnhancedThreeCompatPass.js`

**功能**: 包装 Three.js 原生 Pass（如 SelectiveSSRPass、UnrealBloomPass）

```javascript
class EnhancedThreeCompatPass extends Pass {
    constructor(threePass, name, passType) {
        this.threePass = threePass;         // 原生 Three.js Pass
        this.passType = passType;           // 类型: "ssr", "bloom", "generic"
        this.needsSwap = threePass.needsSwap;
    }
    
    render(renderer, inputBuffer, outputBuffer, deltaTime, ...) {
        // 设置缓冲区
        this.setupBuffers(renderer, inputBuffer, outputBuffer);
        
        // 直接调用原生 Pass 的 render
        this.threePass.render(
            renderer,
            this.renderToScreen ? null : outputBuffer,  // writeBuffer
            inputBuffer,                                 // readBuffer
            deltaTime,
            ...
        );
    }
    
    setupBuffers(renderer, inputBuffer, outputBuffer) {
        switch (this.passType) {
            case "ssr":
                // SSRPass 特殊处理：使用 inputBuffer 代替 beautyRenderTarget
                this.threePass.beautyRenderTarget = inputBuffer;
                break;
                
            case "bloom":
                // Bloom 特殊处理
                break;
                
            default:
                // 通用处理：设置 tDiffuse
                if (this.threePass.uniforms?.tDiffuse) {
                    this.threePass.uniforms.tDiffuse.value = inputBuffer.texture;
                }
        }
    }
}
```

**特点**:
- ✅ 包装 Three.js Pass，不修改原始代码
- ✅ 根据 `passType` 做特殊处理
- ✅ 继承原生 Pass 的 `needsSwap` 设置
- ✅ 支持缓冲区映射和转换

**与 EffectPass 的区别**:

| 维度 | EffectPass | EnhancedThreeCompatPass |
|-----|-----------|------------------------|
| **使用场景** | postprocessing 内置 Effect | Three.js 原生 Pass |
| **渲染方式** | EffectMaterial 合成 | 直接调用 Pass.render() |
| **材质系统** | 统一的 EffectMaterial | Pass 自己的材质 |
| **Shader 合成** | 自动合成多个 Effect | 不涉及合成 |
| **性能** | 多Effect可合并为1次渲染 | 每个Pass独立渲染 |
| **扩展性** | 必须实现 Effect 接口 | 任何 Three.js Pass |

## 完整渲染流程

### Demo 场景: `gbuffer-composer.js`

```javascript
// 1. 创建 Composer
const composer = new EffectComposer(renderer);

// 2. 添加 RenderPass (G-Buffer 模式)
const gBufferPass = new RenderPass(scene, camera, null, {
    enableGBuffer: true,
    enableObjectId: true
});
composer.addPass(gBufferPass);

// 3. 添加 SelectiveSSRPass (通过 EnhancedThreeCompatPass 包装)
const ssrPass = new SelectiveSSRPass({ ... });
const compatSSRPass = new EnhancedThreeCompatPass(ssrPass, "SelectiveSSRPass", "ssr");
composer.addPass(compatSSRPass);

// 4. 渲染循环
requestAnimationFrame(function render() {
    composer.render();  // 执行整个管线
    requestAnimationFrame(render);
});
```

### 逐帧渲染流程

```
帧 N 开始
│
├─ EffectComposer.render()
│  │
│  ├─ 1️⃣ RenderPass.render()
│  │   ├─ 保存状态
│  │   ├─ 渲染场景 → outputBuffer (gColor)
│  │   ├─ 渲染 G-Buffer → gBufferRenderTarget
│  │   │   ├─ gColor   (场景颜色)
│  │   │   ├─ gNormal  (世界法线)
│  │   │   ├─ gDepth   (线性深度)
│  │   │   ├─ gPosition (世界坐标)
│  │   │   └─ gObjectId (对象ID，可选)
│  │   └─ 恢复状态
│  │   
│  │   Buffer状态:
│  │   inputBuffer  = [空] (初始)
│  │   outputBuffer = [场景渲染] ✅
│  │   
│  ├─ 交换？NO (RenderPass.needsSwap = false)
│  │
│  ├─ 2️⃣ EnhancedThreeCompatPass.render()
│  │   │
│  │   ├─ setupBuffers()
│  │   │   └─ 根据 passType 做特殊处理
│  │   │
│  │   ├─ threePass.render(renderer, outputBuffer, inputBuffer, ...)
│  │   │   
│  │   │   以 SelectiveSSRPass 为例：
│  │   │   ├─ 阶段1-2: 准备数据 (使用 G-Buffer)
│  │   │   ├─ 阶段3-4: 选择性遮罩生成 (~0.15ms)
│  │   │   ├─ 阶段5-6: SSR 计算 + 模糊 (~0.4ms)
│  │   │   └─ 阶段7: 最终合成
│  │   │
│  │   │   详细流程见: 后处理渲染管线-SelectiveSSR.md
│  │   │
│  │   Buffer状态:
│  │   inputBuffer  = [场景渲染] (来自RenderPass)
│  │   outputBuffer = [场景+后处理效果] ✅
│  │
│  └─ 交换？YES (SelectiveSSRPass.needsSwap = true)
│      inputBuffer  = [场景+SSR反射] (原outputBuffer)
│      outputBuffer = [场景渲染] (原inputBuffer)
│
└─ 渲染到屏幕
   如果是最后一个Pass: renderToScreen = true
   renderer.setRenderTarget(null)
   显示 inputBuffer 内容

帧 N 结束
```

## SelectiveSSRPass 概述

> **详细文档**: 请参考 [后处理渲染管线-SelectiveSSR.md](./后处理渲染管线-SelectiveSSR.md)

### 核心特性

**SelectiveSSRPass** 是一个高级后处理效果，实现选择性屏幕空间反射：

- ✅ **选择性**: 通过深度遮罩只对指定对象计算反射
- ✅ **屏幕空间光线追踪**: 基于像素的实时反射计算
- ✅ **G-Buffer 集成**: 复用法线和深度数据，优化性能
- ✅ **高级特性**: 支持模糊、菲涅尔、距离衰减等

### 渲染阶段概览

```
SelectiveSSRPass.render()
├─ 阶段1: Beauty渲染 ❌ 已优化跳过 (节省 0.3ms)
├─ 阶段2: Normal渲染 ✅ 使用 G-Buffer
├─ 阶段3: 选中对象深度渲染 (~0.1ms)
├─ 阶段4: 深度遮罩生成 (~0.05ms)
├─ 阶段5: SSR 光线追踪 (~0.2ms)
├─ 阶段6: 模糊处理 (~0.2ms)
└─ 阶段7: 最终合成
```

### 关键优化

| 优化项 | 方法 | 收益 |
|--------|------|------|
| **Beauty渲染** | 使用 inputBuffer 代替重复渲染 | -0.3ms |
| **法线纹理** | 使用 gBufferTextures.gNormal | 避免重复渲染 |
| **深度纹理** | 使用 gBufferTextures.gDepth | 避免重复渲染 |

### 为什么需要 renderPass？

```javascript
// renderPass 是 GPU 处理纹理的唯一方式
renderPass(renderer, material, renderTarget) {
    renderer.setRenderTarget(renderTarget);      // 设置输出目标
    this.fsQuad.material = material;             // 设置shader
    this.fsQuad.render(renderer);                // 渲染全屏四边形
    // → 触发 GPU 渲染管线: 输入纹理 → Shader → 输出纹理
}
```

**原因**:
- GPU 无法直接修改纹理像素
- 必须通过渲染管线处理
- 全屏四边形覆盖所有像素
- 每个像素执行片段着色器

## 性能优化原则

### 1. 避免冗余渲染 ✅

**原则**: 检查是否有重复渲染相同内容

**示例** (SelectiveSSR):
- ❌ 问题: RenderPass 和 SelectiveSSRPass 都渲染场景
- ✅ 解决: 直接使用 inputBuffer，跳过重复渲染
- 💰 收益: 节省 0.3ms (约 12%)

### 2. 复用 G-Buffer 数据 ✅

**原则**: 充分利用已有的渲染数据

**可复用数据**:
- 场景颜色: `inputBuffer.texture`
- 法线纹理: `gBufferTextures.gNormal`
- 深度纹理: `gBufferTextures.gDepth`
- 世界坐标: `gBufferTextures.gPosition`

### 3. 实测优于猜测 ⚠️

**教训**: 批量渲染优化反而性能下降

**原因**:
- 过度优化干扰 GPU 管线
- 现代 GPU 对状态切换优化很好
- 纹理缓存可能失效

**结论**: 基于实测数据优化，避免过度优化

### 4. 权衡质量与性能 🎚️

**可选优化方案**:

| 方案 | 收益 | 代价 | 适用场景 |
|-----|------|------|---------|
| 降低分辨率 | 50-75% | 质量下降 | 移动端/低端设备 |
| 分帧计算 | 50% | 更新延迟 | 静态场景 |
| 禁用模糊 | 10-20% | 噪点增加 | 高帧率需求 |
| 减少步数 | 20-40% | 反射精度 | 远景反射 |
